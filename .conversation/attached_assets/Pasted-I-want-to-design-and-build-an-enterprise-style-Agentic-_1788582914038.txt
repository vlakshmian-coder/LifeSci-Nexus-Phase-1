I want to design and build an enterprise-style Agentic AI application called “LifeSci Nexus” for the Life Sciences / MedTech domain.
The purpose is to assist qualified human teams with clinical-validation and regulatory-readiness preparation by retrieving authoritative evidence, analysing submitted documents, identifying potential information gaps, maintaining project continuity across interactions, verifying evidence, and producing a structured preliminary readiness report for human review.
The intended architecture includes:
- a Supervisor / Orchestrator
- an Intake & Planning Agent
- a Document Intelligence Agent
- a Regulatory Evidence Agent
- a Clinical / Regulatory Gap Analysis Agent
- an Evidence Verification Agent
- a Readiness Report Agent
- a Human Review Gate
- RAG for authoritative external evidence
- project-scoped persistent memory for previous project inputs, outputs, findings, reviewer comments and decisions
- auditability, source traceability, guardrails and evaluation
Important architectural principle:
RAG should provide evidence-grounded external knowledge and remain the source of truth for regulatory information.
Project memory should provide continuity and historical project context, but must not silently become authoritative regulatory evidence.
I want to build this as a serious portfolio / enterprise architecture showcase, not as a simple chatbot.
For now, do NOT build the application or modify code.
First analyse this concept and propose:
1. the recommended system architecture,
2. the responsibilities and interactions of each agent,
3. how RAG and project memory should work together,
4. the data and information flow,
5. the major components and dependencies,
6. a sensible MVP,
7. risks and safeguards for a regulated Life Sciences context,
8. and an incremental implementation plan.
Do not invent regulatory requirements or claim that this system provides regulatory, clinical or medical advice.
I want the architecture to be understandable and explainable by the project owner.
